# Уведомления о лимитах Codex

## Версия и история изменений

Текущая согласованная версия исходного кода: **`1.1.1`**. История от `0.1.0` до `1.1.1` с контрольными коммитами записана в [CHANGELOG.md](CHANGELOG.md); текущий номер — в [VERSION](VERSION). Номера ранних этапов назначены ретроспективно по согласованной схеме SemVer, а не по существовавшим в момент разработки тегам или GitHub Releases.

Первым стабильным выпуском считается `1.0.0` (разовое обновление часового пояса). Добавление кнопки «📊 Лимиты» относится к `1.1.0`, исправление повторных уведомлений о 0% — к `1.1.1`.

**Версия работающего экземпляра на VPS отдельно не подтверждена.** Изменение номера или кода в GitHub не обновляет сервер.

Telegram-бот [@Ky3aLimitsbot](https://t.me/Ky3aLimitsbot) проверяет через Codex App Server пятичасовой и недельный лимиты раз в минуту.

## Уведомления и команды

- При остатке 20%, 10% и 5% бот сообщает о пройденном пороге. Если за одну проверку пройдено несколько порогов, приходит одно сообщение.
- При фактическом переходе к 0% бот один раз сообщает, что лимит исчерпан. Сдвиг расчётного времени обновления не вызывает повторное сообщение.
- После сброса любого из двух лимитов приходит уведомление об обновлении.
- В предупреждениях о порогах и сбросах показаны остаток и время следующего обновления обоих лимитов. Кнопка **«📊 Лимиты»** и команда `/limits` показывают их по запросу.
- Telegram отображает время обновления по часовому поясу устройства. Для клиентов без поддержки такого отображения в сообщении есть резервное время Минска.
- При потере доступа к данным бот отправляет одно предупреждение и сообщает о восстановлении после успешной проверки.

Бот принимает команды и геопозицию только из настроенного личного чата. Команду `/limits` можно переименовать через `TELEGRAM_STATUS_COMMAND` в `/etc/codex-limit-bot.env`.

## Часовой пояс и тихие часы

С **02:00 до 10:00** по сохранённому часовому поясу автоматические уведомления отправляются без звука. Проверки продолжаются, сообщения не откладываются. Ответ на `/limits` приходит обычным способом в любое время.

По умолчанию используется время Минска. После переезда нажмите в чате кнопку **«📍 Обновить часовой пояс»**: Telegram однократно отправит текущую геопозицию, бот сохранит определённый по ней часовой пояс и подтвердит его. Живая трансляция не обновляет зону. В чате доступны две кнопки: «📊 Лимиты» и «📍 Обновить часовой пояс». Если клавиатура скрыта, отправьте `/start` или `/timezone`.

Координаты используются только для определения часового пояса и не записываются в файл состояния. Сохранённая зона находится в `/var/lib/codex-limit-bot/timezone.json`.

## Размещение и данные

Бот работает на VPS в `/opt/codex-limit-bot` от пользователя `codexbot`. Таймер `codex-limit-bot.timer` запускает проверку каждую минуту, а `codex-limit-bot-listener.service` принимает сообщения Telegram. Состояние отправленных уведомлений хранится в `/var/lib/codex-limit-bot/state.json`.

Секреты не входят в репозиторий: вход Codex хранится в закрытом каталоге пользователя `codexbot`, токен Telegram и ID чата — в `/etc/codex-limit-bot.env` с правами `0600`.

Проверка служб: `systemctl status codex-limit-bot.timer codex-limit-bot-listener.service`. Разовая проверка лимитов: `systemctl start codex-limit-bot.service`. Отправка коммита в GitHub не обновляет VPS: сервер обновляется отдельно после проверки и согласования.

## Разработка на Windows и macOS

Основная и единственная локальная рабочая папка проекта на Windows — `%USERPROFILE%\Documents\Codex\Projects\codex-limit-bot`. Новый локальный чат Codex для этого проекта нужно открывать в этой папке: перенос истории чата не меняет его рабочий каталог. Итоговое размещение описано в [LOCAL-LAYOUT.md](LOCAL-LAYOUT.md).

GitHub хранит исходный код. Ветка `main` содержит одобренную основную версию, а `dev` используется для текущей разработки и ручной синхронизации между Windows-ПК и MacBook. В `main` изменения попадают только после необходимых тестов и отдельного явного разрешения пользователя. На новом устройстве клонируйте репозиторий и переключитесь на рабочую ветку:

```sh
git clone https://github.com/Ky34/codex-limit-bot.git
cd codex-limit-bot
git switch --track origin/dev
```

Нужен Python 3.11 или новее. Создайте виртуальное окружение и установите зависимости из `requirements.txt`. На macOS:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

На Windows (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Перед работой проверяйте состояние репозитория и безопасно получайте изменения `dev` без переписывания истории. После получения прочитайте [`PROJECT_STATE.md`](PROJECT_STATE.md). Перед переходом на другое устройство обновите этот файл, если изменился существенный контекст, затем зафиксируйте и отправьте изменения в `dev`. При отсутствии файловых и контекстных изменений пустой коммит не создаётся. Если есть локальные изменения, расхождение истории или конфликт, сначала сохраните и разберите работу.

Фразы «Выгрузи изменения», «Синхронизируй проект» и «Закинь на GitHub» означают отправку проверенных изменений этого проекта в `dev`. Фразы «Загрузи изменения», «Подтяни проект» и «Получи изменения с GitHub» означают безопасное получение `dev`. Публикация в `main` выполняется отдельной командой и требует конкретного разрешения. Эти команды не обновляют VPS и не запускают второго экземпляра бота.

GitHub не синхронизирует локальные чаты, секреты и рабочее состояние бота на VPS. Для доступа к секретам с другого устройства используется Bitwarden.
