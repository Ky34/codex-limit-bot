# Состояние проекта codex-limit-bot

## Назначение

Telegram-бот сообщает о пятичасовом и недельном лимитах Codex, порогах остатка, сбросах и временной недоступности данных. Также поддерживаются запрос текущих лимитов и определение часового пояса пользователя.

## Ветки и устройства

- Основная ветка: `main`.
- Рабочая ветка: `dev`.
- Устройства разработки: `windows-pc`, `macbook`.
- Обычная межустройственная синхронизация выполняется через `dev`.
- Публикация в `main` требует отдельного конкретного разрешения пользователя.
- Разрешённая публикация проверенного commit в `main` запускает автоматический production deploy после успешного CI.

## Устройство проекта

- Основная логика находится в `bot.py`.
- Шаблоны служб и таймера находятся в репозитории. На активном VPS проект расположен в `/opt/codex-limit-bot`, рабочее состояние — в `/var/lib/codex-limit-bot`, секретное окружение — в `/etc/codex-limit-bot.env`; службы запускаются от пользователя `codexbot`.
- Автоматические проверки находятся в `tests/`.
- Секреты, авторизация Codex и рабочие файлы состояния VPS в Git не входят.
- Архитектура и production deployment описаны в `docs/DEPLOYMENT.md`; deploy-скрипты находятся в `deploy/`, production-зависимости зафиксированы в `requirements.lock`.
- CI/CD использует immutable releases, exact SHA `origin/main`, restricted SSH, `flock`, атомарное переключение `current`, health-check и автоматический rollback.

## Следующий шаг

- Наблюдать production с новой двухошибочной логикой и убедиться на естественном кратковременном сбое, что одиночный timeout/503 больше не создаёт пару warning/recovery.
- Отдельным будущим изменением улучшить безопасную диагностику Telegram `getUpdates`: сохранять полезный тип исходной сетевой ошибки/HTTP status без bot token, полного Telegram URL и других секретов.
- Отдельно остаётся продуктовая задача: не считать восстановлением доступа сброс только одного окна лимита, если второй лимит всё ещё блокирует использование.

## Ограничения и риски

- Отправка коммитов в `dev` не обновляет работающего бота; разрешённая публикация проверенного commit в `main` запускает автоматический production deploy после успешного CI.
- Нельзя запускать локальный Telegram listener с рабочим токеном одновременно с серверным listener.
- Нельзя помещать в Git токены, файлы авторизации, локальные состояния или содержимое `.codex`.
- Ручное обновление, остановка production VPS или обход штатного CI/CD требуют отдельного разрешения; обычный путь обновления — проверенный commit в `main` → GitHub Actions → exact-SHA deploy.
- Lock-файл рассчитан на CPython 3.12 и Linux x86_64; смена платформы требует его осознанной пересборки.
- Автоматический rollback покрывает штатную ошибку deployment, но не гарантирует восстановление после отключения питания; для такого случая нужен описанный ручной откат и резервная копия.
- Не использовать старый VPS как рабочую площадку или цель деплоя: компоненты бота с него удалены.
