# Инструкции проекта Codex Limit Bot

- Перед работой прочитай `README.md` и проверь `git status --short --branch` и удалённую ветку. GitHub хранит версионируемый код этого проекта.
- `main` содержит одобренную основную версию бота. `dev` — постоянная рабочая ветка для разработки и ручной синхронизации между Windows-ПК и MacBook. Переноси `dev` в `main` только после необходимых тестов и отдельного явного разрешения пользователя.
- Перед началом работы и после получения `dev` прочитай `PROJECT_STATE.md`. Перед выгрузкой обновляй его только при существенном изменении контекста, решений, проверок, проблем или следующего шага.
- Команды «Выгрузи изменения», «Синхронизируй проект» и аналогичные относятся в этом чате только к `codex-limit-bot`: проверь состав изменений и отправь содержательный коммит в `dev`. Команды «Загрузи изменения», «Подтяни проект» и аналогичные безопасно получают `dev` без перезаписи локальной работы. Если изменений нет, не создавай пустой коммит.
- Публикация в `main` является отдельной операцией. Сохраняй историю; не используй squash, rebase, force-push и не объединяй ветки без отдельного согласования.
- Бот работает на VPS. Отправка изменений в GitHub сама по себе не обновляет сервер. Перед конкретным обновлением рабочего бота требуется разрешение пользователя; сохрани прежнюю версию на сервере и проверь службы после установки.
- Не запускай локальный Telegram listener с рабочим токеном одновременно с серверным listener: оба процесса будут забирать команды из одного чата.
- Не добавляй в Git токены, сессии Codex, файлы `.env`, `auth.json`, `state.json`, `updates.json` или каталог `.codex`. Доступ к секретам на другом устройстве организуй через Bitwarden.
- После изменений в коде запусти `python3 -m unittest discover -s tests -v` (в Windows также подойдёт `python`). Для изменений только документации не повторяй тесты без конкретного риска. Перед сменой устройства проверь чистоту рабочей копии и отправку нужных коммитов в GitHub.
